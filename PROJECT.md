# NestledBurrow: bootstrap проекта

## Назначение

`PROJECT.md` — точка восстановления долгого контекста. Пользователь описывает замысел Лиду, Лид готовит компактное архитектурно осмысленное ТЗ, Codex реализует его end-to-end.

## Канонические владельцы

- `GAME.md` — продуктовый вижн, фактическая зрелость и пользовательский verdict.
- `ROADMAP.md` — активная/следующая работа и постоянные Task numbers.
- `LEAD.md` — перевод замысла в компактное ТЗ и Fast/Strict route.
- `ARCHITECTURE.md` — подтверждённые runtime-границы и условные точки выделения.
- `REVIEW.md` — опциональная независимая приёмка сложных или нескольких PR.
- `AGENTS.md` — обязательный контракт Codex.
- `LIBRARY.md` — необязательная карта устойчивых кодовых адресов.
- `FAST_LOOP.md` — человеческие аудиты скорости, не обязательный контекст реализации.
- `ASSETS.md` / `BINARY_IMPORT.md` — provenance и Lead-owned binary delivery.
- `tasks/*.md` — только действительно большие, зависимые или возобновляемые контракты.

GitHub issues не являются обязательной памятью проекта.

## Постоянная идентичность

Каждая согласованная задача получает последовательный номер в `ROADMAP.md` до Codex prompt:

```text
Task #001 — Первая расчистка участка
```

Заголовок повторяется в первой строке prompt, branch/PR identity, поле `Task:` и сообщениях ролей. После открытия PR:

```text
Task #001 — Первая расчистка участка (PR #81)
```

Task number не меняется при feedback, repair, rebase или повторной приёмке.

## Восстановление нового чата

Пользователю достаточно сказать:

```text
привет, ты лид
```

или:

```text
привет, ты интегратор
```

До первого содержательного ответа:

### Лид

1. читает `PROJECT.md`, `LEAD.md`, `GAME.md` и `ROADMAP.md`;
2. проверяет актуальный `main`, открытые PR и последние релевантные merges;
3. понимает фактическую реализацию и пользовательские verdict;
4. при архитектурном риске открывает `ARCHITECTURE.md`;
5. не просит пользователя пересказывать игру или GitHub.

### Интегратор

1. читает `PROJECT.md`, `REVIEW.md`, `GAME.md` и `ROADMAP.md`;
2. самостоятельно находит применимые открытые PR;
3. связывает их с Task identity;
4. выполняет команду без запроса номеров PR, веток, SHA или CI.

Команда `проверь все PR` означает обработать все открытые PR в `main`.

## Роли

- **Пользователь** владеет продуктовым/художественным выбором, балансом и ощущением.
- **Лид** переводит свободное описание в компактное системно безопасное ТЗ.
- **Codex** реализует, показывает preview, публикует, ждёт CI, исправляет и сливает одну задачу end-to-end.
- **Интегратор** опционально проводит независимую приёмку сложной очереди.

Feedback-итерации пользователя являются продуктовой работой и не ограничиваются ради метрик скорости.

## Репозиторий и runtime

- Репозиторий: `downlimit/NestledBurrow`.
- Опубликованная игра: https://downlimit.github.io/NestledBurrow/.
- Phaser 4.2.1, Vite, браузерная 2D-игра, логическое разрешение `320×180`.

## Что уже опубликовано

Текущий `main` содержит:

- единый top-down мир, камеру, edge-grid таверну и collision;
- keyboard/mobile input и восемь направлений;
- NPC, диалоги и мини-квест;
- JSON-safe versioned save/reload и `NEW GAME`;
- RU/EN, Pixelify Sans, HUD/options/audio и Pages;
- непрерывное время, сон, потребности и energy/resource loop;
- брёвна, камни, рубины и интерактивные facilities;
- canonical furniture PNG и случайный музыкальный playlist;
- runtime build mode с library, surfaces/walls/furniture, drag prediction, demolition и undo;
- developer tuning и desktop/mobile Browser E2E;
- `WorldScene` как composition root с локальными выделенными runtime-компонентами.

Этот список не равен продуктовому verdict. Точная зрелость находится в `GAME.md`.

## Текущее направление

Игрок превращает заброшенный летающий остров и таверну в живое персональное заведение, добывает и перерабатывает ресурсы, обслуживает гостей, настраивает процессы, создаёт помощников и собирает поселение из аллодов.

Активный slice и следующий Task находятся в `ROADMAP.md`.

## Основной процесс

```text
замысел пользователя
→ Task # и компактное ТЗ
→ одна ветка
→ для visual/runtime: managed preview и любое нужное число feedback-итераций
→ пользовательское `принято`
→ Fast: минимальная активная публикация; Strict: один конкретный локальный gate
→ Ready PR с auto-merge
→ полный GitHub CI
→ один repair только при failure
→ merge и актуальный main
```

После `принято` принятый здоровый preview не проверяется заново полным локальным check/build/E2E без конкретного риска. Полный repository contract принадлежит PR CI. Детали находятся в `AGENTS.md` и `FAST_LOOP.md`.

## Сохранение контекста

- продукт/зрелость → `GAME.md`;
- Task numbers/очередь → `ROADMAP.md`;
- архитектурные сигналы → `ARCHITECTURE.md`;
- роли → `LEAD.md`, `REVIEW.md`;
- исполнение → `AGENTS.md`;
- адреса → `LIBRARY.md`;
- assets → `ASSETS.md`, `BINARY_IMPORT.md`.

Открытый PR не является завершением. Для visual/runtime пользовательское принятие предшествует PR; final-head CI после принятия разрешает merge. Невидимые технические задачи проходят автоматический маршрут.
