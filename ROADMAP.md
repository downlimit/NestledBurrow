# NestledBurrow: roadmap и текущее исполнение

## Назначение

`ROADMAP.md` отвечает:

1. что делается сейчас;
2. что проверяется следующим.

Состояние механик и пользовательский verdict принадлежат `GAME.md`. Код, checks и merged PR доказывают техническую реализацию.

## Идентификаторы

Каждая согласованная работа получает постоянный номер до Codex prompt:

```text
Task #001 — Первая расчистка участка
```

После открытия PR используется Task-first адрес:

```text
Task #001 — Первая расчистка участка (PR #81)
```

- номера последовательны и не переиспользуются;
- один пользовательский результат сохраняет identity от prompt до merge;
- branch: `task/<номер>-<slug>`;
- Base SHA Лид проверяет непосредственно перед запуском.

**Следующий свободный номер:** `Task #040`.

## Статусы

- `Запланировано` — направление согласовано;
- `Готово к запуску` — prompt подготовлен;
- `В работе` — Codex выполняет задачу;
- `PR открыт` — идёт CI/review;
- `Смёржено, ждёт теста` — код в `main`, verdict ещё нет;
- `Принято` / `Переделать` / `Отклонено` — решение пользователя;
- `Завершено` — техническая/process работа завершена;
- `Заблокировано` — указан конкретный blocker.

## Сейчас

### Task #039 — Первый гость и вывеска «Открыто / Закрыто»

**Статус:** `Готово к запуску после merge Task #038`.

**Наблюдаемый результат:** перед входом в таверну стоит интерактивная вывеска, которая сохраняет состояние `Открыто / Закрыто`. Периодически появляется не более одного гостя. Он использует минимальный grid-pathfinding поверх существующего collision environment и текущую систему движения. При закрытой таверне гость подходит к вывеске, останавливается, смотрит на неё и уходит. При открытой — входит, проверяет сервировочный стол из Task #038, при наличии блюда забирает его, идёт к месту за столом, ест и уходит; без блюда ограниченно ждёт и затем уходит. Гости, уже прошедшие вывеску, завершают визит даже после закрытия.

**Зависимость:** Task #038 должна быть принята и смёржена в `main`; точный Base SHA определяется непосредственно перед запуском.

**Граница:** без денег, заказов, репутации, очереди, нескольких гостей, выбора блюд, сложного расписания, character-character collision или общего AI framework.

### Task #038 — Мини-игра готовки и выставление блюда на стол

**Статус:** `Готово к запуску`.

**Наблюдаемый результат:** стартовый запас картофеля проходит цепочку `сырой → подготовленный → готовое блюдо → блюдо на сервировочном столе` через отдельные разделочный стол и газовую плиту. Оба активных шага используют мини-игру с таймером, движущимся индикатором, случайной уменьшающейся зелёной зоной, кнопкой `Постараться` и combo-бонусами `3 / 6 / 18 / 32 / 64` секунд. Kitchen state и состояние блюда на столе сохраняются.

**Граница:** без гостей, оплаты, заказов, общего inventory framework, огорода, колодца и сложной production-chain.

### Task #037 — Не тратить CI на заведомо устаревшую базу

**Статус:** `Завершено` после merge этой ветки.

**Наблюдаемый результат:** при публикации уже принятой локальной работы после изменения `main` Codex сначала перечитывает актуальный `AGENTS.md`, делает accepted commit потомком текущего `origin/main` через rebase или cherry-pick и только затем впервые push/open PR. Заведомо одноразовый CI на stale head запрещён; нормальный маршрут использует один final-head CI.

**Причина:** публикация Task #035 открыла PR на устаревшей базе, дождалась зелёного CI, затем сделала rebase и запустила второй CI. Это не повысило качество и увеличило end-to-end время принятой задачи.

### Task #036 — Ускорить публикацию и стабилизировать Windows-инструменты

**Статус:** `Завершено`.

**Наблюдаемый результат:** пользовательские feedback-итерации явно считаются продуктовой работой и не ограничиваются. После `принято` Fast-задача за несколько минут активной работы доходит до Ready PR: принятый healthy preview не дублируется локальным full check/build/E2E без конкретного риска, а полный contract остаётся PR CI. Python checks используют portable launcher; preview и focused-E2E outputs живут в OS temp; worktree не смешивает уровни прав. Ретроспектива #030–#035 и актуальная архитектурная память закреплены в канонических документах.

**Граница:** без ослабления final-head CI, удаления Browser E2E, ограничения пользовательского feedback, изменения gameplay, dependencies или общего rewrite `WorldScene`.

### Task #035 — Исправить мобильное меню строительства и джойстик (PR #136)

**Статус:** `Принято`.

**Фактическое состояние:** accepted local commit опубликован, rebased на актуальный `main`, прошёл final-head `Classify Scope`, `Validate` и `Browser E2E`, затем смёржен как `5682120`.

**Продуктовый результат:** RU/EN-тексты library корректны в `320×180` и coarse-pointer viewport; library прокручивается finger drag с инерцией без ложного выбора/строительства; tap выбирает asset. Центр джойстика совпадает с touch даже у края, sprint-ring может выходить за viewport, а его alpha уменьшена вдвое без изменения радиуса, threshold и movement math.
