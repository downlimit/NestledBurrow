# NestledBurrow: roadmap и текущее исполнение

## Назначение

`ROADMAP.md` отвечает:

1. что делается сейчас;
2. что проверяется следующим.

Состояние механик и пользовательский verdict принадлежат `GAME.md`. Код, checks и merged PR доказывают техническую реализацию.

## Идентификаторы

Каждая согласованная работа получает постоянный номер до Codex prompt:

```text
Task #001 — Первая расчистка участка
```

После открытия PR используется Task-first адрес:

```text
Task #001 — Первая расчистка участка (PR #81)
```

- номера последовательны и не переиспользуются;
- один пользовательский результат сохраняет identity от prompt до merge;
- branch: `task/<номер>-<slug>`;
- Base SHA Лид проверяет непосредственно перед запуском.

**Следующий свободный номер:** `Task #041`.

## Статусы

- `Запланировано` — направление согласовано;
- `Готово к запуску` — prompt подготовлен;
- `В работе` — Codex выполняет задачу;
- `PR открыт` — идёт CI/review;
- `Смёржено, ждёт теста` — код в `main`, verdict ещё нет;
- `Принято` / `Переделать` / `Отклонено` — решение пользователя;
- `Завершено` — техническая/process работа завершена;
- `Заблокировано` — указан конкретный blocker.

## Сейчас

### Task #040 — Сохранять расстановку уровня как стартовую и редактировать коллайдеры деревьев

**Статус:** `Готово к запуску`.

**Наблюдаемый результат:** в debug-панели есть действие, которое фиксирует текущую расстановку всех управляемых build mode элементов как стартовую конфигурацию уровня. Чистый запуск и `NEW GAME` создают мир из последней сохранённой стартовой расстановки; последующие runtime-правки не становятся новым дефолтом, пока действие не нажато снова. Декоративные деревья, посаженные через build mode, выбираются в режиме редактирования коллайдеров по видимой области и используют тот же профильный override-контракт, что камни, брёвна и другие редактируемые объекты.

**Граница:** это developer-authoring стартового уровня, а не сохранение пользовательских построек в gameplay session. Без общего редактора карт, импорта/экспорта уровней, истории версий расстановки, новой системы ассетов или массового rewrite `WorldScene`.

### Task #037 — Не тратить CI на заведомо устаревшую базу

**Статус:** `Завершено`.

**Наблюдаемый результат:** при публикации уже принятой локальной работы после изменения `main` Codex сначала перечитывает актуальный `AGENTS.md`, делает accepted commit потомком текущего `origin/main` через rebase или cherry-pick и только затем впервые push/open PR. Заведомо одноразовый CI на stale head запрещён; нормальный маршрут использует один final-head CI.

### Task #036 — Ускорить публикацию и стабилизировать Windows-инструменты

**Статус:** `Завершено`.

**Наблюдаемый результат:** пользовательские feedback-итерации явно считаются продуктовой работой и не ограничиваются. После `принято` Fast-задача за несколько минут активной работы доходит до Ready PR: принятый healthy preview не дублируется локальным full check/build/E2E без конкретного риска, а полный contract остаётся PR CI. Python checks используют portable launcher; preview и focused-E2E outputs живут в OS temp; worktree не смешивает уровни прав.
