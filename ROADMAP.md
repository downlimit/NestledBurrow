# NestledBurrow: roadmap и текущее исполнение

## Назначение

`ROADMAP.md` отвечает:

1. что делается сейчас;
2. что проверяется следующим.

Состояние механик и пользовательский verdict принадлежат `GAME.md`. Код, checks и merged PR доказывают техническую реализацию.

## Идентификаторы

Каждая согласованная работа получает постоянный номер до Codex prompt:

```text
Task #001 — Первая расчистка участка
```

После открытия PR используется Task-first адрес:

```text
Task #001 — Первая расчистка участка (PR #81)
```

- номера последовательны и не переиспользуются;
- один пользовательский результат сохраняет identity от prompt до merge;
- branch: `task/<номер>-<slug>`;
- Base SHA Лид проверяет непосредственно перед запуском.

**Следующий свободный номер:** `Task #043`.

## Статусы

- `Запланировано` — направление согласовано;
- `Готово к запуску` — prompt подготовлен;
- `В работе` — Codex выполняет задачу;
- `PR открыт` — идёт CI/review;
- `Смёржено, ждёт теста` — код в `main`, verdict ещё нет;
- `Принято` / `Переделать` / `Отклонено` — решение пользователя;
- `Завершено` — техническая/process работа завершена;
- `Заблокировано` — указан конкретный blocker.

## Сейчас

### Task #042 — Надёжное строительство и единый authoring-профиль ассетов

**Статус:** `Готово к запуску`.

**Наблюдаемый результат:** снос стены выбирает точное ребро стены и не перескакивает на соседнюю параллельную стену от смещения курсора на несколько пикселей. Замкнутые комнаты достраиваются без зазоров: совместимые стены могут соприкасаться и образовывать узлы независимо от собственных runtime-коллайдеров, при этом дубликаты и реальные пересечения по-прежнему запрещены.

Горизонтальные, вертикальные стены и стеновые узлы получают независимые стабильные authoring-профили коллайдера. Изменение одного профиля немедленно применяется ко всем существующим и будущим экземплярам только этого варианта.

Debug authoring получает режим редактирования пивота выбранного asset-профиля: однопиксельный маркер, drag и смещение стрелками по `1 px`. Одно действие сохраняет коллайдер и пивот. Versioned authoring backup содержит стартовую топологию и полный набор эффективных asset-профилей, чтобы браузерный черновик можно было перенести и канонизировать без потери данных.

Стартовые и построенные стены используют одну топологию, один renderer и одни asset-профили; параллельные legacy/current wall-prefab paths удаляются. Build library включает существующие малые/крупные брёвна и камни, рубиновую жилу, разделочный стол, плиту и стол выдачи. Authorable resource nodes используют общий profile-driven runtime вместо отдельного пути только для посаженного дерева.

**Архитектурная граница:** задача активирует отмеченное в `ARCHITECTURE.md` локальное выделение world-facing build rendering/orchestration из `WorldScene`; без общего rewrite сцены, ECS или новой gameplay-save схемы.

**Preview acceptance:** required.

### Task #041 — Надёжно сохранять веб-правки коллизий и топологии (PR #146, repair PR #147, repair PR #148)

**Статус:** `Смёржено, ждёт теста`.

**Фактическое состояние:** final repair смёржен в `main` как `fc3ec8b`. Authoring runtime регистрирует активную `WorldScene`, переживает `NEW GAME`/scene restart и восстанавливает browser-local layout после готовности build/facility/debris runtimes.

**Наблюдаемый результат:** опубликованный статический веб-билд сохраняет подтверждённые коллизии, стены, полы, мебель, растения и остальную стартовую расстановку в browser-local authoring draft даже тогда, когда серверный endpoint записи исходников недоступен. Перезапуск сцены, страницы и новый deployment на том же origin загружают этот draft раньше checked-in defaults.

Debug-панель прямо различает `сохранено в браузере` и `записано в исходники проекта`, не выдаёт сохранённую локально работу за ошибку и позволяет скачать/загрузить одну versioned JSON-копию коллизий и топологии.

**Граница:** GitHub Pages остаётся статическим хостингом и без отдельной авторизованной backend/GitHub App не может самостоятельно коммитить изменения в репозиторий. Browser draft не является gameplay-save построек и может быть удалён только очисткой данных сайта; JSON-копия служит переносимым резервным контуром.

### Task #040 — Каноническая стартовая расстановка, коллайдеры и посаженные деревья (PR #144)

**Статус:** `Принято`.

**Фактическое состояние:** пользователь разрешил публикацию; final-head `Classify Scope`, `Validate` и `Browser E2E` прошли, PR смёржен в `main` как `89bfc6d`.

**Наблюдаемый результат:** debug-действие сохраняет текущую управляемую расстановку как стартовую конфигурацию проекта. Кнопка `Применить в проект` в редакторе коллайдеров записывает текущие профильные offsets в канонический модуль проекта, поэтому после следующего build они не возвращаются к старым значениям. Локальное хранилище используется только как черновик и fallback при недоступной записи проекта.

Посаженное через build mode дерево относится к группе `Растения`, остаётся доступным для посадки, выбирается редактором по видимой кроне без второго визуального коллайдера, физически использует один редактируемый collider ствола, рубится топором и после полного сруба даёт `6` дерева.

**Граница:** это developer-authoring стартового уровня и collider defaults, а не сохранение пользовательских построек как общей gameplay-системы. Без общего редактора карт, импорта/экспорта уровней, истории версий, выращивания растений или массового rewrite `WorldScene`.

### Task #037 — Не тратить CI на заведомо устаревшую базу

**Статус:** `Завершено`.

**Наблюдаемый результат:** при публикации уже принятой локальной работы после изменения `main` Codex сначала перечитывает актуальный `AGENTS.md`, делает accepted commit потомком текущего `origin/main` через rebase или cherry-pick и только затем впервые push/open PR.
